# 난청 노인용 청각 알림 시스템

## 1. 프로젝트 소개

난청 노인을 위해 초인종, 화재경보 등 중요한 소리를 감지하고 시각 및 촉각 알림으로 전달하는 대학교 캡스톤 프로젝트입니다. 소리를 듣기 어려워 생활 속 주요 신호를 놓치는 문제를 해결하는 것을 목표로 합니다.

저비용 하드웨어, 로컬 동작, 오픈소스 공개, 사용자 친화성을 지향합니다. 통신 방식은 Wi-Fi SoftAP + UDP로 확정했으며, 현재는 실제 보드에서 기초 통신과 수신부 절전을 검증한 단계입니다. S3·C3 간 이벤트 전송·ACK와 C3 자동 Light-sleep을 구현했고, 절전 확인 후 연속 100개 이벤트에서 ACK 100/100·재전송 0·실패 0을 기록했습니다. 이 결과는 TEST 이벤트를 이용한 해당 실험의 결과이며, 소리 감지·분류·알림 기능은 구현 전입니다. 실제 화재경보 등의 감지 성능과 신뢰성은 아직 검증되지 않았습니다. 오픈소스 라이선스 종류는 TBD입니다.

## 2. 시스템 개요

- 송신부 (Transmitter / Main module): ESP32-S3에서 마이크 입력, 소리 분석 및 이벤트 분류를 수행할 예정입니다.
- 수신부 (Receiver / Child module): ESP32-C3에서 이벤트 정보를 수신하고 시각·촉각 알림을 제공할 예정입니다.
- 통신: Wi-Fi SoftAP 기반으로 확정했습니다. 기초 실험은 UDP + ACK·재전송 방식이며, 실제 보드에서 C3 절전·이벤트 수신·ACK를 검증합니다.
- 머신러닝: Ubuntu PC에서 학습·평가·변환을 수행하고, 경량 모델을 ESP32-S3에 배포하는 것을 목표로 합니다.

계획된 전체 데이터 흐름은 다음과 같습니다. 통신 테스트 코드 외의 기능은 구현 예정입니다.

```text
소리 입력 (예정)
→ ESP32-S3 오디오 입력 (예정)
→ 소리 분석 (예정)
→ 이벤트 분류 (예정)
→ Wi-Fi SoftAP + UDP 무선 통신 (실물 이벤트·ACK·C3 절전 검증)
→ ESP32-C3 TEST 이벤트 수신 (구현·검증, 실제 소리 이벤트는 향후 통합)
→ LED / 진동 / 화면 알림 (예정)
```

시스템은 송신부에서 소리를 분석하고 이벤트 결과만 수신부로 전달하는 구조를 목표로 합니다. 현재 통신 코드는 원시 오디오 대신 TEST 이벤트를 전송합니다. 기초 테스트의 이벤트 형식은 [통신 프로토콜 v1](docs/communication/README.md)에 정의했습니다.

## 4. 통신 방식

LILYGO T7 S3 v1.1을 SoftAP·송신부로, ESP32-C3 SuperMini를 STA·수신부로 구성했습니다. 외부 공유기 없이 S3가 Wi-Fi 네트워크를 만들고 C3가 접속합니다. 16바이트 UDP 패킷으로 약 3초마다 TEST 이벤트를 보내며, ACK가 없으면 300ms 간격으로 최초 전송 포함 4회 시도하고 ACK가 없으면 이벤트를 유지하여 2초 후 다음 재시도 묶음을 시작합니다. 세션·순번 기반 중복 처리 억제와 자동 재접속도 구현했습니다. 상세 설정은 2.4GHz·채널 6·WPA2-PSK, UDP 포트 4210이며 현재 수신부는 1대입니다.

C3는 Wi-Fi 연결을 유지하면서 Modem-sleep과 자동 Light-sleep을 사용하고, S3는 SoftAP를 계속 유지합니다. Deep-sleep은 사용하지 않습니다. C3는 약 10초마다 HELLO와 절전 상태를 보고하며, S3는 HELLO가 35초 넘게 없으면 응답 없음으로 표시하지만 주소와 미전달 이벤트를 유지하며 재전송합니다. C3는 끊김 감지 즉시 재접속을 시도하고, IP를 다시 받으면 HELLO를 바로 보냅니다.

현재 보관 범위는 RAM의 TEST 이벤트 1개이며 ACK 대기 중에는 다음 TEST 생성을 미룹니다. 여러 실제 알림의 큐·우선순위·유효시간과 S3 재부팅 후 보존은 미구현입니다. 재접속·이벤트 보관 변경의 실물 검증은 아직 수행하지 않았으며 아래 측정은 변경 전 펌웨어 기준입니다.

[기초 통신 코드 및 빌드·테스트 절차](communication_tests/softap_udp/README.md)와 [프로토콜 v1](docs/communication/README.md)을 준비했습니다. 실제 보드의 연결·이벤트·ACK·C3 절전 검증 결과는 [2026-10-30 실험](docs/test_results/low_power_2026-10-30.md)에 기록합니다. 초기 빌드·코드 검토 기록은 [2026-10-29 검증 기록](docs/test_results/softap_udp.md)에서 확인할 수 있습니다.

### 실물 검증 결과와 기록

2026-10-30 기준 결과입니다. 원본 로그와 분석 JSON은 [실험 기록](docs/test_results/low_power_2026-10-30.md#근거)에 연결되어 있습니다.

| 항목 | 결과 |
| --- | --- |
| C3 실제 Light-sleep | SDK 절전 성공 횟수 111 → 3519 증가 |
| 절전 확인 후 연속 100개 TEST 이벤트 | ACK 100/100, 재전송 0, FAILED 0 |
| ACK 왕복 시간 | 최소 9ms / 평균 55.79ms / 최대 130ms |
| S3 재시작 후 C3 자동 재연결 | S3 부팅 후 약 5.5초에 재등록 및 첫 ACK |
| C3 자체 재시작 후 복구 | 미확인 |
| 소비전류·배터리 사용 시간 | 미측정 |

ACK는 C3 소프트웨어의 이벤트 수신 처리 확인입니다. 실제 LED·진동 동작이나 사용자의 인지를 확인하는 응답은 아닙니다. ACK 유실 주입·중복 억제·거리 시험은 이번 실물 실험에서 수행하지 않았으며, 전송 성공을 보장하는 단계는 아닙니다.

[통신 모니터·로그 분석 도구](tools/communication/README.md)로 두 보드의 로그와 무선 상태 보고를 확인하고, 고유 이벤트 수·ACK·재전송·실패·왕복 시간·절전 성공 횟수를 분석합니다. 모니터 로그는 기본적으로 `/tmp/hearing-alert-monitor.*`에 저장하므로, 보관할 원본은 `docs/test_results/evidence/`에 별도로 복사하고 실험 조건과 결과를 문서로 남깁니다.

`communication_tests/espnow/`는 이전 검토 후보의 참고 영역으로 보존합니다. ESP-NOW는 현재 개발 대상에서 제외합니다.

## 5. 머신러닝 계획

향후 음향 데이터 수집 → 전처리 → 학습 → 평가 → 경량화/양자화 → ESP32-S3 배포 순서로 개발할 예정입니다. 학습, 전처리, 평가 및 모델 변환은 초기에는 Ubuntu PC에서 수행할 계획입니다.

YAMNet 기반 접근 또는 YAMNet에서 아이디어를 가져온 경량 음향 이벤트 분류 모델을 검토할 예정입니다. YAMNet 적용 여부, 모델 구조, 데이터셋 및 도구는 TBD이며, 현재 모델 다운로드나 머신러닝 코드 구현은 수행하지 않았습니다. 최종 목표는 경량화된 모델을 ESP32-S3에서 추론 가능하도록 만드는 것입니다.

## 7. 개발 환경

Ubuntu의 ESP-IDF v5.5.5를 사용합니다. `communication_tests/softap_udp/`는 ESP32-S3와 ESP32-C3를 각각 빌드하는 ESP-IDF 프로젝트입니다. Python 기반 ML 환경은 향후 구성 예정입니다. ROS 2 또는 colcon 프로젝트는 아닙니다.

## 8. 개발 워크플로

현재 통신 프로젝트는 다음 흐름으로 개발·검증합니다.

```text
코드 수정 → 빌드 → 보드 플래시 → 실물 테스트 → 로그 분석·결과 기록
→ git status / git diff → git add → git commit → git push
```

- 빌드 (build): 소스코드를 컴파일하여 실행 가능한 결과물을 생성하고 컴파일·링크 오류를 확인하는 과정입니다. 실제 보드에서의 실행 가능 여부와 동작은 플래시 후 테스트로 확인합니다.
- 커밋 (commit): 현재 변경사항을 Git 이력으로 기록하는 과정입니다.
- 푸시 (push): 커밋을 GitHub 원격 저장소에 업로드하는 과정입니다.

현재는 기초 통신 및 C3 절전 코드를 빌드·플래시해 실험합니다. 최종 펌웨어 통합은 [시스템 구조](docs/architecture/README.md)에 정리했습니다. 커밋·푸시는 별도 요청 시 수행합니다.
