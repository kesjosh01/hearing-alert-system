C3가 이탈한 동안 S3는 해당 순번을 보관하고 재시도했다. 새 세션 등록 이후 같은 이벤트의 ACK를 받았다. 로그의 `ACK ... attempts=`는 현재 재시도 묶음의 횟수이므로 전체 송신 횟수와 다를 수 있다. 위 표는 TX 로그를 직접 세어 누적 횟수를 기록했다.

19:24:45 및 19:28:42 부근에 같은 C3 MAC의 leave가 기록되고, 이후 같은 MAC이 다시 join했다. S3의 이후 ACK는 저장된 출력의 반복이 아니라 순번이 증가하는 새 응답이다. C3 USB 콘솔 중단만으로 Wi-Fi 이탈 여부를 판단하지 않고, station·세션·ACK 기록을 함께 확인했다.

## 복구 작업

1. 기존 S3 16MB 플래시 전체를 백업하고 복구 직전 기록 대상 영역을 추가 백업했다. 두 백업의 겹치는 영역이 일치했다.
2. 백업 이미지에는 Arduino 관련 문자열이 있었고 이번 통신 테스트 앱과 달랐다. 부팅 중 SHA-256 경고가 있었지만 이것만으로 플래시 고장을 확정하지 않았다.
3. 저장소의 S3 통신 테스트를 빌드·기록한 뒤 정상 부팅, AP 생성, C3 접속과 ACK를 확인했다. 복구 후 캡처에서 기존 SHA-256 comparison failed 문구는 관측되지 않았다.
4. RESET으로 포트가 다시 생성될 때 수동 ACL이 사라지는 문제는 `/etc/udev/rules.d/70-hearing-alert-s3-a4cb8ff63e34.rules`로 처리했다. 실제 uaccess 태그와 사용자 읽기·쓰기 권한을 확인했다.
5. 실제 플래시는 16MB이나 기존 시험용 빌드의 4MB 설정을 유지했다. 부팅 시 큰 실제 용량과 이미지 헤더의 차이를 알리는 경고가 있으며, 이번 작은 시험 앱은 정상 실행됐다.
