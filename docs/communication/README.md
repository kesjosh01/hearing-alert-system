# S3 ↔ 수신부 이벤트 프로토콜 v1

S3(송신부, LILYGO T7 S3)가 소리 이벤트를 수신부(Seeed Studio XIAO ESP32-C6)로 보내고 ACK를 받는 규격과 현재 펌웨어의 전송 정책입니다.

| 날짜 | 변경 |
| --- | --- |
| 2026-11-07 | v1 프레임에 소리 이벤트 ID·수신 검사·동시 감지·벡터를 정의 |
| 2026-11-15 | 제품 펌웨어 구현(`firmware/`). 반복 송신 + ACK(A안), 큐·TTL·재시도 기본값, 300ms 목표 절전(DTIM 3) |
| 2026-11-17 | 수신부를 ESP32-C3 SuperMini → XIAO ESP32-C6으로 변경. ACK 시점을 "UI 큐 접수"에서 "알림 화면을 LCD로 보낸 뒤"로 변경 |

프레임 형식·ID·벡터는 2026-11-07 이후 바뀌지 않았습니다. 필드·로그 이름의 "C3"(`c3_session`, `C3_PM` 등)는 보드 변경 뒤에도 "수신부"를 뜻하는 이름으로 유지합니다. 2026-11-07 원문(구현 지시·작성 당시 코드 현황 포함)은 Git 이력(커밋 `a60f21b`까지)에 있습니다.

## 통신 시험 로그

- [261111_통신원거리테스트v1](261111_통신원거리테스트v1.md): 약 4m·같은 층·같은 방 초기 시험(TEST 펌웨어, C3 SuperMini). 전체 169개 이벤트의 ACK, C3 재접속 및 최종 안정 구간 44개를 기록했다. 사용자 요청으로 종료하여 동일 세션 연속 100개 목표는 미완료다.

## 1. 데이터 흐름

```text
S3:  ML 판정 → 명시적 ID 매핑 → ha_publish_event(s)()
     → 대기열(8) → v1 인코더 → UDP 유니캐스트(반복 송신) → 수신부
수신부: 송신원·프레임·ID 검사 → 중복 검사 → UI 큐 접수
     → 진동 시작·알림 화면을 LCD로 전송 → ACK(받은 세 필드 복사) → S3 재전송 중지
```

- **S3:** 모델 클래스 번호를 그대로 보내지 않습니다. 제어 코드의 매핑 표로 아래 고정 ID로 바꿉니다. 미매핑 결과·배경음은 보내지 않습니다. 감지 임계값·시간 창·반복 감지 억제는 ML/제어 정책입니다([모델 연결 안내](../ml/MODEL_HANDOFF.md)). S3 자체 LED에도 같은 ID를 쓰며, LED는 ACK를 기다리지 않습니다.
- **수신부:** 모델 정보를 해석하지 않습니다. 등록 ID만 화면·진동 UI로 넘깁니다. 접수하지 못하면 중복 기록을 갱신하지도 ACK하지도 않습니다.

## 2. 고정 이벤트 ID와 확장 규칙

이벤트 ID는 unsigned 32비트 정수다. 메시지 종류 `EVENT=2`와 이벤트 ID는 다른 필드다.

| ID (hex / decimal) | 이름 | 의미 | 사용 |
| --- | --- | --- | --- |
| `0x00000000` / 0 | 예약 | 이벤트 아님 | EVENT에서 거부 |
| `0x00000001` / 1 | TEST | 기존 통신 실험 | 실험 전용 예약, 소리 이벤트로 재사용 금지 |
| `0x00000100` / 256 | FIRE_ALARM | 화재경보 소리 감지 | v1 소리 이벤트 |
| `0x00000101` / 257 | DOORBELL | 초인종 소리 감지 | v1 소리 이벤트 |

v1 소리 수신기는 FIRE_ALARM·DOORBELL 두 ID만 처리한다. TEST는 양 보드에서 진단 옵션(`HA_DIAG_ALLOW_TEST_EVENT`)을 켰을 때만 허용하며, TEST를 화재 알림으로 해석해서는 안 된다. 나머지는 미등록 ID로 폐기하고 알림·성공 ACK·중복 기록 갱신을 하지 않는다. 진단 로그는 허용한다.

향후 ID는 이 표에 중복 없이 추가하고 양 팀의 매핑·수신 허용 목록·벡터를 함께 갱신한다. 할당한 ID는 의미를 바꾸거나 삭제 후 재사용하지 않는다. 신규 소리 ID는 `0x00000102`부터 미할당 값을 순차 배정한다. ID만 추가하고 프레임 의미가 같으면 v1을 유지할 수 있으나 구형 수신기는 이를 거부하므로 **수신부를 먼저 배포**한다(절차: [ha_comm](../../firmware/common/ha_comm/README.md#소리-종류-추가-절차)). 필드 순서·크기·인코딩 또는 기존 필드 의미를 바꾸면 새 프로토콜 버전을 사용한다. 기능 협상은 현재 없다.

## 3. 전송 형식과 수신 검사

**UDP 데이터그램 1개 = 프레임 1개 = 소리 이벤트 1개**다. 정확히 16바이트의 바이너리이며 JSON·CSV·UTF-8 이벤트 이름·ASCII hex 문자열을 보내지 않는다. 아래 hex는 바이트 표시법이다. 별도 줄바꿈·NUL·길이 필드·타임스탬프·confidence·비트마스크는 없다.

| 오프셋 | 바이트 수 | 필드 | 인코딩 / EVENT의 값 |
| --- | --- | --- | --- |
| 0 | 2 | magic | ASCII `HA` = `48 41` |
| 2 | 1 | version | unsigned 8비트, `01` |
| 3 | 1 | type | unsigned 8비트, EVENT=`02` |
| 4 | 4 | session | unsigned 32비트 big-endian, S3 부팅 세션 |
| 8 | 4 | seq | unsigned 32비트 big-endian, 1부터 증가 |
| 12 | 4 | event_id / value | unsigned 32비트 big-endian, 위 ID |

세션은 S3의 `esp_random()` 32비트 값이며 0도 유효하다. 난수 충돌 가능성이 있다. seq=0은 EVENT에서 무효다. 순번 소진 시 새 세션을 만들고 seq=1부터 시작한다. 같은 이벤트 재전송은 세션·순번·ID를 그대로 유지한다. 신규 이벤트는 새 순번을 사용한다.

제어·진단 패킷도 같은 헤더·길이·바이트 순서를 유지한다.

| type | 방향 | session | seq | value |
| --- | --- | --- | --- | --- |
| HELLO=1 | 수신부 → S3 | 수신부 부팅 세션 | 0 | 0 |
| EVENT=2 | S3 → 수신부 | S3 부팅 세션 | 이벤트 순번 | 이벤트 ID |
| ACK=3 | 수신부 → S3 | 받은 EVENT 값 복사 | 받은 EVENT 값 복사 | 받은 EVENT 값 복사 |
| PM_STATS=4 | 수신부 → S3 | 수신부 부팅 세션 | SDK Light-sleep 성공 횟수 | 거절 횟수 |
| POWER_STATE=5 | 수신부 → S3 | 수신부 부팅 세션 | auto Light-sleep 설정 0/1 | Wi-Fi MIN_MODEM=1 |

선택 기능인 v2 TIME_SYNC(28바이트)는 [ha_comm](../../firmware/common/ha_comm/README.md#v2-time_sync-신규-확장-선택-기능)에 정의돼 있으며 v1 알림 경로에 영향을 주지 않는다.

수신 검사는 다음 순서로 한다.

1. 실제 수신 데이터그램 길이가 정확히 16인지 확인한다. 짧거나 긴 메시지는 폐기한다. 16바이트 버퍼로 긴 데이터그램을 잘라 정상으로 인정하면 안 된다(구현은 최대 프레임 + 1바이트 수신 버퍼로 초과를 검출한다).
2. magic=`48 41`, version=1인지 확인한다. 알 수 없는 버전은 v1로 추측해 파싱하지 않는다.
3. type·방향·송신 IP·포트를 검사한다. 수신부 EVENT는 AP IP에서 포트 4210으로 온 것만, S3 ACK는 등록 수신부 IP·포트에서 온 것만 처리한다. 진단 패킷은 등록된 수신부 세션도 확인한다. 미등록 종류는 폐기한다.
4. 필드를 명시적으로 big-endian 디코딩한다. EVENT는 seq≠0, 등록된 소리 ID인지 확인한다. ACK는 대기 이벤트의 세 필드가 모두 일치해야 대기를 해제한다. HELLO·상태 패킷은 위 표의 필드 조건을 적용한다.
5. 유효 이벤트만 중복 검사 후 UI에 접수한다. 이미 접수한 이벤트이면 알림을 반복하지 않는다(화면 전송 전이면 ACK도 보류, 후이면 ACK만 다시 보냄). 새 이벤트는 접수 성공 뒤 기록하고, 알림 화면을 LCD로 보낸 뒤 ACK한다. 잘못된 프레임은 UI 호출·ACK·중복 상태 변경 없이 폐기한다.

**ACK의 의미:** 수신부가 그 알림 화면을 LCD로 오류 없이 보냈다는 확인이다. LCD에서 값을 읽는 선이 없어 LCD가 빠졌거나 화면·백라이트가 고장 난 경우는 기본 설정으로 알 수 없고(선택 기능 `HA_DISP_READBACK`으로 LCD 응답까지 확인 가능), 사용자가 봤다는 증명도 아니다. 애플리케이션 인증이 없어 IP·포트 검사는 발신자 인증을 보장하지 않는다.

## 4. 동시 감지

한 추론 구간에서 두 소리가 검출되면 S3 매핑 결과는 두 ID의 목록이다. 한 개로 덮어쓰거나 두 ID를 OR하지 않는다. 동일 배치의 생성 순서는 FIRE_ALARM, DOORBELL로 정하고 각각 고유 순번을 부여한다(`ha_publish_events()`).

순번 기반 중복 판정과 맞도록 S3는 **stop-and-wait**로 전송한다. 첫 이벤트 ACK 후 두 번째를 전송하며, 그동안 두 번째 이벤트는 대기열에 보관된다. 수신부는 첫 알림이 진행 중이어도 두 번째를 독립적으로 접수한다. 화면에서는 화재가 우선이고 초인종은 벨 배지로 함께 표시된다([수신부 안내](../../firmware/receiver_c6/README.md#화면과-진동-데모-디자인-유지)). 병렬 송신으로 바꾸면 역순 수신을 누락시키는 현 중복 판정을 재설계해야 한다.

## 5. 테스트 벡터

아래는 **규격에서 도출한 예시**이며 실기기 송수신 캡처가 아니다. session=`0x12345678`(305419896), 올바른 송신원, 초기 중복 기록 없음, 접수 성공을 가정한다. 각 줄은 정확히 16바이트의 UDP payload이며 공백·개행 문자는 전송하지 않는다. 공통 코어 호스트 시험(`firmware/common/ha_comm/test/host/`)이 실제 인코더·디코더로 이 벡터를 검사한다.

| 벡터 | 정확한 전송 데이터 (hex) | 기대 디코딩 |
| --- | --- | --- |
| FIRE_ALARM EVENT | `48 41 01 02 12 34 56 78 00 00 00 01 00 00 01 00` | version=1, type=2, session=305419896, seq=1, event_id=256 (FIRE_ALARM) |
| FIRE_ALARM ACK | `48 41 01 03 12 34 56 78 00 00 00 01 00 00 01 00` | type=3, EVENT의 session·seq·ID 일치 |
| DOORBELL EVENT | `48 41 01 02 12 34 56 78 00 00 00 02 00 00 01 01` | version=1, type=2, session=305419896, seq=2, event_id=257 (DOORBELL) |
| DOORBELL ACK | `48 41 01 03 12 34 56 78 00 00 00 02 00 00 01 01` | type=3, EVENT의 session·seq·ID 일치 |

잘못된 메시지 예시는 FIRE_ALARM EVENT를 기준으로 아래처럼 바꾼다. 변경 후 전체 바이트열이 시험 입력이며 오프셋은 0부터다.

| 입력 / 조건 | 기대 동작 |
| --- | --- |
| 마지막 바이트 삭제 (15바이트), 또는 끝에 `00` 추가 (17바이트) | 길이 오류, 폐기·ACK 없음 |
| 오프셋 0을 `00`으로 변경 | magic 오류, 폐기·ACK 없음 |
| 오프셋 2를 `02`로 변경 | 미지원 버전, 폐기·ACK 없음 |
| 오프셋 3을 `FF`로 변경 | 미등록 종류, 폐기·ACK 없음 |
| 오프셋 8~11을 `00 00 00 00`으로 변경 | seq=0, 폐기·ACK 없음 |
| 오프셋 12~15를 `00 00 01 02`로 변경 | 미등록 ID=258, 폐기·알림·ACK 없음 |
| 오프셋 12~15를 `00 00 00 00` 또는 `00 00 00 01`로 변경 | 예약 또는 TEST ID, 소리 수신 모드에서 거부 |
| 정상 FIRE_ALARM을 같은 세션·순번으로 재수신 | 첫 접수 1회만, 동일 ACK 재전송 |
| seq=2 접수 후 같은 세션의 seq=1 도착 | stop-and-wait 정책상 stale, 알림 없이 ACK. 병렬 송신 금지 이유 |
| 정상 payload지만 잘못된 IP·포트 또는 방향 | 폐기·ACK 없음 |
| S3가 기다리는 ACK와 session·seq·ID 중 하나라도 다름 | ACK 무시, 해당 이벤트 대기 유지 |
| 수신부 UI 큐 접수 실패 | 알림 접수·중복 기록·성공 ACK 없음. 재전송 시 다시 접수 가능해야 함 |

| 우선순위 | 송신은 FIFO. 화재 우선은 옵션(기본 꺼짐), 선점 없음. 화면에서는 화재 우선 | 송신: 향후 정책 경계 / 화면: 2026-11-17 구현 |
| 수신부 중복 기록 | 최근 S3 세션 4개의 최대 seq와, 최근 8건의 (session, seq, id). RAM 보관 | 지연된 이전 세션 패킷의 재알림 방지. 수신부 재부팅 시 사라짐 |
| ACK 시점 | 알림 화면을 LCD로 보낸 뒤 (`HA_RX_ACK_ON_DISPLAY`, 기본 켬) | 2026-11-17 사용자 결정. 끄면 UI 큐 접수 시점(11-15 방식) |
| UI 미연결 | ACK하지 않음 | 2026-11-15 사용자 결정 |
| 화면이 안 뜰 때 | 3초 뒤 LCD 재초기화, 6초 뒤 수신부 재부팅, 연속 3회 뒤 진동 전용 모드(ACK 없음) | 2026-11-17 구현, 제안값 |

**보장 범위:** exactly-once 전달, 영구 보존, 기한 내 전달은 보장하지 않습니다. S3가 재부팅되면 대기 이벤트가 사라지고, 수신부가 재부팅되면 중복 기록이 사라져 같은 알림이 다시 울릴 수 있습니다(at-least-once). AP 버퍼의 크기·보존 시간은 보장되지 않으므로 반복 송신과 ACK로 보완합니다.
