## 벤치: C6 단독 (LCD·모터·버튼 미연결)

보드: XIAO ESP32-C6 (ESP32-C6FH4 rev v0.2, 내장 플래시 4MB), USB만 연결. 펌웨어: 화면 읽기 확인(`HA_DISP_READBACK`)·시연 옵션을 켠 빌드. 부팅 후 약 10초 동안의 USB 로그를 확인했습니다.

| 확인 | 결과 |
| --- | --- |
| 부팅 | RF 스위치 `GPIO3=0 GPIO14=0`, GC9A01 초기화 명령 전송, 모터·버튼·UI 시작, UI 소비자 연결까지 정상. S3가 꺼져 있어 `STA disconnected reason=201`(AP 없음) 반복은 정상. 15초 뒤 자동 Light-sleep 진입은 로그 수집 시간 밖이라 **확인하지 않음** |
| LCD 없이 상태 읽기 (40MHz, 풀업 없음) | 모든 레지스터 `0x00` → 읽기 속도를 4MHz로 낮추고 SDA 내부 풀업을 거는 것으로 수정 |
| LCD 없이 상태 읽기 (4MHz, SDA 풀업) | 모든 레지스터 `0xff` 고정 → `RDDPM=0xff -> panel NOT responding` 판정, 바로 60초 주기 화면 재시도 모드로 들어감 ✔ |

LCD를 연결한 상태의 읽기 확인(아래 6번)이 끝나기 전까지 `HA_DISP_READBACK`은 기본으로 꺼 둡니다.

## 실기기 시험 절차 (미수행)

[2026-11-15 절차](product_firmware_2026-11-15.md#실기기-후속-시험-미수행)를 C6·UI 기준으로 고친 최신본입니다. 모니터: `HEARING_FIRMWARE=product bash tools/communication/monitor.sh S3_PORT C6_PORT`(수신부 포트 이름은 기존 `HEARING_C3_PORT` 그대로). 펌웨어 리비전·sdkconfig·원본 양측 로그와 결과를 분리해 기록합니다. **진단 주입 결과를 소리 인식 성공으로 보고하지 않습니다.**

1. **전원 인가 자동 연결:** S3 `S3 AP ready … DTIM=3`, C6 `RF switch: GPIO3=0 GPIO14=0` → `STA got IP` → S3 `receiver registered (new_peer)`.
2. **화면·진동 단독:** 핀맵대로 LCD·모터·버튼을 연결합니다. 부팅 진동 1회와 시계 화면을 확인합니다. `HA_UI_DEMO_BUTTON_CYCLE=y`로 초인종·긴급 화면과 진동 패턴, 색(`HA_DISP_INVERT`)·방향(`HA_DISP_MADCTL`)을 확인합니다.
3. **API → 무선 → 화면 → ACK:** S3 진단 주입을 켭니다. C6 `EVENT accepted … ; ACK after display` → `ha_ui: screen FIRE` → `EVENT displayed … -> ACK (N ms after reception)` → S3 `ACK seq=…`가 이어지고 세 필드가 일치하는지 봅니다. N과 S3 재전송 횟수를 기록합니다. 동시 2건은 FIRE seq N, DOORBELL seq N+1이고 화면은 화재 + 벨 배지여야 합니다.
4. **ACK 유실·중복:** C6의 ACK 송신을 임시로 막은 빌드에서 `duplicate` 재ACK와 알림 1회를 확인합니다. 미등록 ID·잘못된 길이 주입도 시험합니다.
5. **화면 복구:** (화면 읽기 확인을 켠 상태에서) LCD를 뺀 채 주입 → 3초 뒤 재초기화 요청, 6초 뒤 재부팅, 연속 3회 뒤 진동 전용 모드 로그를 확인합니다. LCD를 다시 꽂으면 60초 안에 화면이 돌아오고 남은 알림이 ACK되는지 봅니다. 재부팅 뒤 S3 재전송으로 화면에 뜨기까지의 시간을 기록합니다.
6. **LCD 상태 읽기 2단계:** LCD를 연결하고 부팅 로그 `probe` 줄에서 `RDDMADCTL=0x08`, `RDDPM=0x9c`(0x14 비트 켜짐, 0x60 비트 꺼짐)인지 봅니다. `byte0_if_dummy_bit` 쪽이 맞으면 1비트 보정을 넣고, LCD를 꽂아도 `0xff`면 이 모듈은 읽기를 지원하지 않는 것입니다.
7. **단절·재부팅:** C6 전원을 끈 뒤 S3 `station left`·적재, 복구 뒤 같은 seq로 ACK, C6 재부팅(`c3_rebooted`), S3 재부팅(새 세션), 35초 초과 stale, TTL 만료를 확인합니다.
8. **300ms 목표 절전:** `C3_PM sleep_count` 증가(실제 절전 진입), ACK 왕복 분포(약 0~310ms + 화면 전송 시간), 전류계로 DTIM=1/3과 화면·백라이트 켜짐/꺼짐의 평균 전류를 비교합니다. 설정 활성화만으로 절전 성공으로 판정하지 않습니다.
9. **시각 확장:** S3에 시각 공급자를 구현한 뒤 TIME_SYNC 수신, 시계 표시, 인터넷 장애 시 알림이 정상인지 확인합니다.

## 미검증

실제 LCD 표시(색·방향), 진동 세기·리듬 체감, 버튼으로 Light-sleep 깨우기, 표시까지 걸리는 시간과 ACK 왕복, LCD를 연결한 상태의 상태 읽기, LCD를 뺐을 때의 복구 동작, 화면·백라이트 소비전류, C6의 실제 절전 진입. C3 SuperMini에서 측정한 2026-10-30·11-11 결과는 C6에 그대로 적용되지 않습니다.
